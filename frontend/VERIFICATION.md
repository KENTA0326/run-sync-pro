# フロントエンド「通信」機能の検証手順

API 共通処理・インターセプター・型定義が正しく動くかを確認するための手順です。

## 前提

- バックエンドが `http://localhost:8080` で起動していること
- DB（PostgreSQL）が起動しており、バックエンドが接続できること
- 検証用ユーザーがいること（いなければ下記「0. 準備」で作成）

---

## 0. 準備（必要なら）

### バックエンド・DB を起動

```bash
# プロジェクトルートで
docker compose up -d db backend
```

### 検証用ユーザー作成

`test.http` の「ユーザー登録のテスト」を実行するか、フロントのサインアップ画面から  
`ken` / `ken@example.com` / `password123` で登録してください。

---

## 1. フロントエンド起動

```bash
cd frontend
npm run dev
```

ブラウザで **http://localhost:3000** を開く（Nuxt のデフォルトポート）。  
バックエンドの CORS が `http://localhost:3001` の場合は、起動時にポートを指定します。

```bash
npm run dev -- --port 3001
```

→ **http://localhost:3001** で開く。

---

## 2. 検証チェックリスト

### 2-1. ログイン成功（API 共通・型定義）

1. **http://localhost:3000**（または 3001）にアクセス
2. ログインページ（`/login`）に遷移する
3. 登録済みの **メールアドレス** と **パスワード** を入力して「ログイン」
4. **期待**: 「ログイン成功！」と表示され、トップ（`/`）に遷移する
5. 開発者ツール → Application → Local Storage に `auth_token` が保存されていることを確認

→ **共通 API（useApi）と型（LoginRequest/LoginResponse）が動いています。**

---

### 2-2. ログイン失敗（エラー表示・getErrorMessage）

1. ログインページで **誤ったパスワード** を入力して「ログイン」
2. **期待**: 「メールアドレスまたはパスワードが正しくありません」など、バックエンドの `error` メッセージが表示される
3. 存在しないメールで試した場合も、同様にエラーメッセージが表示されること

→ **API エラー文言の共通処理（getErrorMessage）が動いています。**

---

### 2-3. 認証付き API（インターセプター：トークン自動付与）

バージョン付き API は `/api/v1/...` を前提とする（例: `GET /api/v1/shoes`）。

1. ログインに成功した状態で **シューズ** または **走行ログ** ページを開く（一覧を取得する）
2. **期待**: 一覧が表示される（401 にならない）
3. 開発者ツールの Network で **`/api/v1/shoes` など** のリクエストを見る → **Request Headers に `Authorization: Bearer <token>` が付いていること**

（プロフィール確認用のエンドポイントは `GET /api/v1/users/me`。レガシー別名は `GET /auth/me` も残している。）

→ **インターセプターによる「トークン自動付与」が動いています。**

---

### 2-4. 401 時のインターセプター（トークン削除・ログインへリダイレクト）

1. ログインした状態で、開発者ツール → Application → Local Storage の `auth_token` を **適当な文字列に書き換える**（無効トークンにする）
2. **シューズ** ページを再読み込みする（または走行ログ一覧を再度開く）
3. **期待**:
   - バックエンドが 401 を返す
   - フロントでトークンが削除される（Local Storage の `auth_token` が消える）
   - **ログインページ（`/login`）にリダイレクトされる**

→ **401 時のインターセプター（clearToken + navigateTo('/login')）が動いています。**

---

## 3. まとめ

| 項目                     | 確認内容                           |
|--------------------------|------------------------------------|
| ログイン成功             | 共通 API・型・トークン保存         |
| ログイン失敗             | エラーメッセージ表示（getErrorMessage） |
| 認証付き API             | Authorization ヘッダー自動付与     |
| 401 時                   | トークン削除＋ログインへリダイレクト |

上記 4 つがすべて期待どおりなら、「通信」まわりの実装は問題なく動いています。
